# Сервис управления лимитами и блокировками платёжных операций B2B-клиентов

**Pet-project**, выполненный в роли **системного аналитика**. 
Сервис предназначен для автоматизации контроля расходов сотрудников B2B-клиентов: установки лимитов, мгновенной блокировки карт и проверки транзакций в реальном времени.

## Проблема и ценность продукта
Компании с большим штатом сотрудников не могут оперативно контролировать корпоративные расходы. Ручной контроль (звонки в банк, бумажные заявки) приводит к задержкам и финансовым потерям.

**Решение:** Веб-сервис, который позволяет финансовому директору устанавливать лимиты на сотрудников, мгновенно блокировать карты и получать историю трат. В основе системы - автоматическая проверка каждой транзакции на соответствие лимитам и блокировкам.

## Моя роль в проекте
- Сформулировал бизнес-цель и KPI продукта.
- Описал бизнес-правила (иерархия лимитов, Maker-Checker, мультивалютность).
- Написал User Stories с критериями приемки (AC).
- Спроектировал процесс проверки платежа BPMN.
- Спроектировал модель данных (ER-диаграмма).
- Разработал спецификацию API (OpenAPI/Swagger) для интеграции с платежным шлюзом.
- Составил тест-кейсы для проверки ключевых сценариев.

## Ключевой функционал
- **Иерархия лимитов:** Банк -> Компания -> Сотрудник (итоговый лимит = минимум из всех).
- **Мгновенная блокировка:** Блокировка карты применяется менее чем за 2 секунды.
- **Maker-Checker:** Изменение лимитов требует подтверждения второго сотрудника (с мгновенным применением и возможностью отката).
- **Мультивалютность:** Конвертация сумм по внутреннему курсу банка при проверке.
- **Временные ограничения:** Лимиты могут действовать только в рабочие часы.
- **Прозрачность:** Сотрудник получает понятную причину отказа в платеже.

## Стек технологий и инструменты
* **Моделирование:** StormBPMN (BPMN 2.0), draw.io (ER-диаграмма).
* **Документация:** OpenAPI/Swagger, Markdown.
* **Методологии:** User Stories, Acceptance Criteria, Maker-Checker.
