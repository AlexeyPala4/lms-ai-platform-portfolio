# Пользовательские истории (User Stories)

Ниже представлены ключевые требования к системе, сформулированные в формате User Stories с критериями приемки. 

## Эпик 1: Управление заданиями (Роль: Преподаватель)

**US-1.1: Создание задания**
*Как преподаватель, я хочу создавать задания с указанием названия, описания, предмета, срока сдачи и файла, чтобы студенты могли их выполнять.*
* **Критерии приемки:**
  * Поля «Название», «Предмет» и «Срок сдачи» обязательны для заполнения.
  * Срок сдачи не может быть установлен в прошлом.
  * Система должна проверить уникальность названия задания для данного преподавателя.
  * При успешном создании задание появляется в списке заданий преподавателя.

**US-1.2: Назначение задания на группы**
*Как преподаватель, я хочу назначать созданное задание на конкретные учебные группы, чтобы его видели только нужные студенты.*
* **Критерии приемки:**
  * Преподаватель может выбрать одну или несколько групп из списка своих групп.
  * Если выбрана опция «Назначить всем группам», задание автоматически привязывается ко всем группам преподавателя.

**US-1.3: Редактирование и удаление задания**
*Как преподаватель, я хочу редактировать или удалять созданные задания, чтобы исправлять ошибки или отменять неактуальные задачи.*
* **Критерии приемки:**
  * При удалении задания система запрашивает подтверждение действия.
  * При удалении задания все связанные ответы студентов также удаляются (каскадное удаление).

## Эпик 2: Проверка и оценивание работ (Роль: Преподаватель)

**US-2.1: Проверка работ с ручной проверкой**
*Как преподаватель, я хочу просматривать ответы студентов и выставлять оценки по пятибалльной шкале, чтобы контролировать успеваемость.*
* **Критерии приемки:**
  * Преподаватель видит текстовый ответ и/или прикрепленный файл студента.
  * Можно добавить текстовый комментарий к оценке.
  * При выставлении оценки статус работы меняется на «Проверено», и студент видит результат.

**US-2.2: Просмотр попыток прохождения тестов**
*Как преподаватель, я хочу видеть все попытки студента по тесту, чтобы анализировать его прогресс.*
* **Критерии приемки:**
  * Отображается список попыток с датой, набранными баллами и оценкой.
  * Преподаватель может изменить итоговую оценку за тест вручную.

**US-2.3: AI-ассистент для проверки**
*Как преподаватель, я хочу получать рекомендации от нейросети GigaChat по проверке текстовых работ, чтобы ускорить процесс оценивания.*
* **Критерии приемки:**
  * AI-ассистент возвращает предлагаемую оценку (2–5) и текстовый комментарий.
  * Рекомендация носит справочный характер; итоговое решение принимает преподаватель (human-in-the-loop).

## Эпик 3: Сдача работ и тестирование (Роль: Студент)

**US-3.1: Сдача работы на проверку**
*Как студент, я хочу отправлять текстовый ответ или прикреплять файл к заданию, чтобы выполнить учебную задачу.*
* **Критерии приемки:**
  * Студент видит только те задания, которые назначены на его учебную группу.
  * Можно отправить либо текст, либо файл (или и то, и другое).
  * До момента проверки преподавателем студент может редактировать или удалить свой ответ.

**US-3.2: Разделение заданий на «Решенные» и «Нерешенные»**
*Как студент, я хочу видеть нерешенные и выполненные задания в двух отдельных колонках, чтобы быстро понимать, что мне еще нужно выполнить, а что уже сдано.*
* **Критерии приемки:**
  * Интерфейс личного кабинета студента реализован в виде двух колонок: левая — «Мои задания», правая — «Выполненные задания».
  * В колонке «Мои задания» отображаются только те задания, по которым у студента еще нет отправленного ответа.
  * В колонке «Выполненные задания» отображаются задания, по которым уже был отправлен ответ.
  * При успешной отправке ответа карточка задания автоматически перемещается из левой колонки в правую без перезагрузки страницы.
  * При успешном удалении ответа карточка задания автоматически перемещается из правой колонки в левую без перезагрузки страницы.

**US-3.3: Детальный разбор ответов**
*Как студент, я хочу видеть детальный разбор своих ответов после теста, чтобы понять свои ошибки.*
* **Критерии приемки:**
  * Правильные варианты выделяются зеленым цветом, неправильные — красным.
  * Отображается количество набранных баллов за каждый вопрос.

## Эпик 4: Администрирование (Роль: Администратор)

**US-4.1: Массовая загрузка данных**
*Как администратор, я хочу загружать списки групп и пользователей из Excel-файлов, чтобы не создавать их вручную.*
* **Критерии приемки:**
  * Система проверяет наличие обязательных колонок в файле.
  * При повторной загрузке существующие записи не дублируются (обновляются).
  * Выводится отчет: сколько записей создано, сколько обновлено.

**US-4.2: Управление ролями и доступом**
*Как администратор, я хочу управлять пользователями и их ролями (Студент, Преподаватель, Администратор), чтобы обеспечить безопасность системы.*
* **Критерии приемки:**
  * Неавторизованные пользователи перенаправляются на страницу входа.
  * Пользователи не имеют доступа к функциям не соответствующих их роли.
